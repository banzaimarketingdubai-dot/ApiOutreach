# Модули Сбора и Обогащения Данных (Scraping & Enrichment Engine)

Инструкции по интеграции внешних источников и обогащению лидов (выполняется внутри Celery Workers).

## 1. Сбор: Google Maps (via Apify)
Основан на существующем скрипте `scraper.py`.
*   **Провайдер:** Actor `compass/google-maps-extractor` в Apify.
*   **Логика:** Celery таска формирует `startUrls` или `searchStrings` (напр: "Barbershop in Dubai"). Вызывает Actor, ждет завершения (через polling Apify API), скачивает Dataset.
*   **Маппинг:** Преобразует ответ Apify в Pydantic схемы (RawLead). Нормализует телефоны, сайты.

## 2. Сбор: 2GIS (Опционально / Планируется)
Для охвата СНГ рынка (РФ, Казахстан) целесообразно добавить 2GIS.
*   **Провайдер:** Официальный API 2GIS (если есть доступ) или веб-парсер (Playwright/BeautifulSoup).
*   **Абстракция:** Создать базовый класс `BaseScraper`, от которого наследуются `GMapsScraper` и `2GisScraper`. Они должны возвращать единый стандартизированный формат (RawLead), чтобы ядро системы не зависело от источника.

## 3. Обогащение: Web Scraping & Contact Extraction
Основан на логике `enrich_contacts.py` и `messenger_checker.py`.
Когда у лида обнаружен веб-сайт, Celery запускает подзадачу `enrich_lead_task`.

**Шаг 3.1: Сканирование сайта**
*   Загрузка главной страницы (HTML).
*   Использование Regex для поиска email-адресов.
*   Поиск ссылок `href` на соц. сети: `instagram.com/`, `facebook.com/`, `t.me/`, `wa.me/`.
*   Поиск скрытых телефонов в шапке/подвале.

**Шаг 3.2: Проверка Мессенджеров (Messenger Checker)**
Если у лида есть мобильный телефон:
*   Опциональная интеграция с API (Green-API/ChatAPI) для проверки наличия аккаунта WhatsApp на данном номере.
*   Использование Telethon (Userbot) для проверки наличия Telegram-аккаунта по номеру.
*   Результат записывается в таблицу `contacts` с тегами `contact_type='whatsapp'`, `source='messenger_checker'`.

**Шаг 3.3: Smart AI Enrichment (Grok / Gemini LLM)**
Извлечение кастомных бизнес-переменных, запрошенных AI-Стратегом (например, `uses_crm`, `has_booking_link`).
*   **Сбор контента:** Скачивается очищенный текстовый контент главной страницы сайта (через BeautifulSoup / Trafilatura).
*   **Batching (Оптимизация лимитов):** Чтобы не делать 1 запрос на 1 сайт, тексты 5-10 сайтов объединяются в один промпт (батч).
*   **LLM API:** Батч отправляется в бесплатные API. Основной движок — **Gemini 3.8** (с автоматическим фолбеком на 3.7 и 3.5 при лимитах) и Grok.
*   **Промпт:** *"Вот тексты 10 сайтов. Для каждого извлеки JSON согласно схеме..."*
*   **Результат:** LLM возвращает массив JSON объектов, которые записываются в колонку `custom_data` в PostgreSQL.

## 4. Revo Score & Audit (Синтез данных)
Алгоритм оценки привлекательности лида для агентства.
*   Если `reviews_count` < 20 -> `Score -= 20`
*   Если `rating` < 4.0 -> `Score -= 15`
*   Если `website` отсутствует -> `Score -= 10`
*   Если нет фото (если данные парсятся) -> `Score -= 10`
*   **Генерация Аудита:** Если скор низкий, генерируется текстовая причина (`audit_notes`): *"Рейтинг 3.8 отпугивает клиентов. Необходимо внедрить Revo для авто-сбора положительных отзывов"*.
*   *Опционально:* Сохранение генерации картинок-аудитов (`revo_visual_renderer.py`) как отдельной функции, которая вызывается перед экспортом данных, а не при сборе, чтобы экономить место на сервере.
